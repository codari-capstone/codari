# AI 기능 정의

2026-09-27 확정. 이 문서가 AI 기능의 기준이며, 계획서(FINAL_PLAN·양식본)의 AI 관련 내용과 다르면 이 문서를 따른다.

## 1. 원칙

1. **기본 채점은 백준과 같다.** 판정 종류(백준과 같은 9가지, 10절)와 채점 진행률만 알려 주고, 판정마다 쉬운 설명을 AI 없이 붙인다. 몇 번째 비공개 테스트에서 틀렸는지, 그 입력과 기대 출력은 공개하지 않는다. 컴파일 에러의 컴파일러 메시지는 백준처럼 보여 주고, 공개 예제에서 난 런타임 에러 원문도 보여 준다.
2. **AI는 사용자가 요청할 때만 개입한다.** 채점만으로 충분한 사용자는 AI 없이 풀 수 있다.
3. **AI는 정답 코드를 주지 않는다.** 틀린 이유와 사고 흐름, 문제를 푸는 원리(수학적 규칙·개념)를 설명한다. 정답 코드 보기 기능은 두지 않는다.
4. **사실과 추정을 구분한다.** 실행 결과로 확인된 내용은 [사실], AI가 코드에서 짐작한 원인은 [추정]으로 표시한다.
5. **추천은 규칙이, 설명은 AI가 맡는다.** 어떤 문제를 추천할지는 풀이 통계로 서버가 정하고, AI는 그 결과를 사람이 읽을 수 있는 분석과 개념 설명으로 바꾼다.

공개 예제는 문제에 적힌 공개 데이터이므로, 예제 실행 결과(기대 출력과 실제 출력 비교)는 AI 없이도 보여 준다.

## 2. 기능 목록

| # | 기능 | 언제 | 사용자에게 보이는 것 |
|---|---|---|---|
| F1 | 오답 원인 분석 | 정답이 아닌 판정 후 **[AI 분석]** 버튼 | 틀린 이유와 틀린 부분(줄 번호)이 바로 표시됨 |
| F2 | 단계별 힌트 | F1 이후 **[힌트 보기]**를 누를 때마다 한 단계씩 | 1단계 관찰 → 2단계 방향 → 3단계 원리. 정답 코드 없음 |
| F3 | 코드 리뷰 | 정답 후 **[AI 리뷰]** 버튼 | 시간·공간 복잡도, 개선점, 다음에 배울 개념 |
| F4 | 학습 리포트 + 다음 문제 추천 | 학습 기록 화면의 **[리포트 보기]** | 취약 개념(통계), AI 분석 문장과 개념 설명, 추천 문제 3개 |

## 3. F1 오답 원인 분석

판정별로 AI가 설명하는 내용은 다음과 같다.

| 판정 | AI 설명 |
|---|---|
| 컴파일 에러 | 컴파일러 메시지를 쉬운 말로 풀이하고 해당 줄을 짚는다 |
| 런타임 에러 | 에러 종류(인덱스 범위 초과, 0으로 나누기, 재귀 깊이 등)와 원인이 될 만한 줄 |
| 시간 초과 | 입력 제한 대비 반복 횟수로 본 복잡도 문제 |
| 메모리 초과 | 메모리를 많이 쓰는 자료구조·재귀 |
| 틀렸습니다 | 출력 형식 문제인지 로직 문제인지, 실패한 경우의 특성(가장 작은 입력, 큰 입력 등)과 의심되는 줄 |

- AI에 전달하는 것: 문제 설명·제약, 제출 코드, 판정, 공개 예제 실행 결과, 컴파일 메시지, 런타임 메시지(공개 예제 케이스만. 비공개 케이스는 런타임 에러 종류만), 실패한 비공개 테스트의 **특성**(원문 값은 전달하지 않음), 문제의 개념 태그.
- 비공개 테스트의 입력·기대 출력 값은 AI 응답에도 나오지 않는다(원칙 1).
- 버튼을 누르면 원인 설명과 힌트 3단계를 **한 번의 AI 호출로 함께 생성해 서버에 저장**한다. 원인 설명만 바로 보내고 힌트는 사용자가 요청한 단계까지만 보낸다. 브라우저에 미리 내려보내지 않는다.

## 4. F2 단계별 힌트

| 단계 | 내용 | 기준 |
|---|---|---|
| 1단계 관찰 | 무엇을 비교하거나 확인해 볼지 | 실행 결과로 확인 가능한 사실에서 출발 |
| 2단계 방향 | 어디를 어떤 방향으로 바꾸면 되는지 | “조건식”, “반복 범위”처럼 고칠 위치와 방향만 |
| 3단계 원리 | 문제를 푸는 원리(수학적 규칙·알고리즘 개념) | 식과 말로 설명하고, 코드는 쓰지 않음 |

- 3단계가 마지막이다. 그 뒤에도 못 풀면 다시 제출하고 새로 분석을 요청한다.
- 몇 단계까지 열었는지 기록해 F4 리포트의 통계로 쓴다.

## 5. 예시: 역방향 피라미드

문제: 정수 n을 입력받아 별 피라미드를 거꾸로 출력한다. n = 3이면 다음과 같다.

```
*****
 ***
  *
```

학습자는 정방향 피라미드(별이 1개, 3개, 5개로 늘어나는 모양)를 구현해 제출했다.

1. **기본 채점**: `틀렸습니다`만 표시된다.
2. **[AI 분석]**
   - [사실] 공개 예제 1에서 기대 출력은 줄마다 별이 5개, 3개, 1개로 줄어드는데, 제출 코드의 출력은 1개, 3개, 5개로 늘어납니다.
   - [추정] 4번째 줄의 반복과 별 개수 식이 정방향 기준으로 작성된 것 같습니다.
3. **[힌트 1단계 관찰]** 예제 출력의 첫 줄과 마지막 줄 별 개수를 세어 보세요. 내 출력과 순서가 어떻게 다른가요?
4. **[힌트 2단계 방향]** 줄 번호 i가 커질 때 별 개수가 어떻게 변해야 하는지 식으로 적어 보세요. 조건식(반복 범위)이나 별 개수 식을 바꾸면 됩니다.
5. **[힌트 3단계 원리]** 정방향의 i번째 줄은 역방향의 (n − i + 1)번째 줄과 같습니다. 정방향 별 개수 2i − 1에서 i 자리에 n − i + 1을 넣으면 별은 2(n − i) + 1개, 앞 공백은 i − 1개가 됩니다.

## 6. F3 코드 리뷰

- 정답 제출에 한해 요청할 수 있다.
- 내용: 시간·공간 복잡도 추정과 문제가 의도한 복잡도 비교, 가독성·중복 등 개선점, 다음에 배울 개념.
- 개선 방향은 설명으로 제시하고, 다시 작성한 전체 코드는 주지 않는다.
- “다음에 배울 개념”은 F4 리포트에 참고 자료로 넘긴다.

## 7. F4 학습 리포트와 다음 문제 추천

**데이터**

- 문제마다 개념 태그 1~3개(예: 반복문 범위, 조건문, 인덱스 변환, 누적합). 팀이 문제를 등록할 때 붙인다.
- 제출 이력(판정, 시도 횟수), 힌트를 연 단계, AI 분석 요청 여부.

**규칙(서버가 계산)**

- 태그별로 해결률, 평균 시도 횟수, 평균 힌트 단계를 구한다.
- 취약 점수 = 0.5 × (1 − 해결률) + 0.3 × (평균 힌트 단계 / 3) + 0.2 × (min(평균 시도 − 1, 4) / 4). 가중치는 더미데이터로 조정한다.
- 추천: 취약 점수 상위 2개 태그에서 아직 풀지 않은 문제를 쉬운 순으로 3개 고른다. 해당 태그의 쉬운 문제를 이미 풀었다면 한 단계 어려운 문제를 고른다.
- 서로 다른 문제를 5개 이상 제출해야 리포트를 만든다.

**AI(문장화)**

- 입력은 서버가 계산한 통계(JSON)와 F3의 “다음 개념” 기록이다.
- 출력은 요약 분석 문장, 취약 개념 설명, 연습 방법이다.
- AI는 추천 목록과 수치를 바꿀 수 없다. 화면의 수치는 서버 값을 그대로 쓰고, AI 문장 안의 수치는 서버가 통계와 대조한다.
- 리포트는 사용자당 하루 1회 새로 만들고, 그 사이에는 저장된 결과를 보여 준다.

## 8. 공통 가드레일

- **정답 코드 금지**: F1·F2 응답에 코드 블록을 쓰지 않는다(식과 설명만). 서버가 코드 블록 여부, 팀이 보유한 검증 정답 코드와의 유사도, 문제 태그의 알고리즘명 노출을 검사하고, 위반하면 한 번 다시 생성한다. 다시 위반하면 결과를 보여 주지 않는다. 검증 정답 코드는 테스트 생성과 이 검사에만 쓰고 사용자에게는 보여 주지 않는다.
- **비공개 테스트 보호**: 비공개 입력·출력 원문은 AI에 전달하지 않고 응답에도 나오지 않는다.
- **사실 검증**: [사실]로 표시된 항목은 서버가 실행 결과와 대조하고, 줄 번호는 실제 코드 범위 안에 있어야 한다.
- **호출 한도와 비용**: AI 분석(F1+F2)과 리뷰(F3)는 합쳐 사용자당 하루 20회까지 쓸 수 있다. 힌트 단계를 여는 것은 추가 호출이 아니다. 리포트(F4)는 하루 1회다. 같은 제출·같은 프롬프트 버전의 결과는 재사용한다. AI는 버튼을 눌렀을 때만 호출하므로 오답마다 자동으로 호출하던 이전 설계보다 호출 수가 적다.
- **장애 대응**: AI 장애나 한도 초과 시에도 채점, 예제 실행, 학습 기록은 정상 동작한다.

## 10. 채점 결과와 쉬운 설명 (AI 없이 표시)

판정 종류와 공개 범위는 백준 온라인 저지를 따른다. 제출 후 “기다리는 중 → 채점 준비 중(컴파일) → 채점 중(진행률 %)”을 거쳐 아래 결과 중 하나가 나오며, 결과 화면에 쉬운 설명과 먼저 확인해 볼 점을 함께 보여 준다.

| 결과 | 쉬운 설명 (화면 문구) | 먼저 확인해 볼 것 |
|---|---|---|
| 맞았습니다!! | 모든 테스트에서 정답과 똑같이 출력했어요. | [AI 리뷰]로 더 빠르거나 읽기 쉬운 방법이 있는지 확인해 보세요. |
| 출력 형식이 잘못되었습니다 | 답의 내용은 맞았지만 띄어쓰기나 줄바꿈이 문제에서 요구한 모양과 달라요. | 줄 끝에 남은 공백, 빠지거나 더해진 빈 줄, 숫자 사이 구분 문자를 예제 출력과 한 글자씩 비교해 보세요. |
| 틀렸습니다 | 프로그램은 끝까지 실행됐지만, 어떤 입력에서 정답과 다른 값을 출력했어요. | 가장 작은 입력과 가장 큰 입력, 빠뜨린 조건, 값이 자료형 범위를 넘는지 확인해 보세요. |
| 시간 초과 | 정해진 시간 안에 프로그램이 끝나지 않았어요. 답이 맞는지는 아직 확인하지 못했어요. | 입력이 가장 클 때 반복이 몇 번 도는지 계산하고, 끝나지 않는 반복이 없는지 확인해 보세요. |
| 메모리 초과 | 허용된 메모리보다 많이 사용했어요. | 배열·리스트의 크기와 재귀 호출의 깊이를 확인해 보세요. |
| 출력 초과 | 정답보다 훨씬 많은 양을 출력했어요. | 출력하는 반복문이 제때 끝나는지, 디버깅용 출력이 남아 있지 않은지 확인해 보세요. |
| 런타임 에러 (종류) | 실행 도중 프로그램이 멈췄어요. 괄호 안이 멈춘 이유예요. | 아래 종류별 설명을 확인해 보세요. |
| 컴파일 에러 | 실행하기 전 문법 검사에서 막혔어요. 결과를 누르면 몇 번째 줄에서 무엇이 문제인지 알려 주는 메시지를 볼 수 있어요. | 괄호·세미콜론·들여쓰기, 선언하지 않은 변수, 제출 언어를 제대로 골랐는지 확인해 보세요. |
| 채점 불가 | 서버 문제로 채점하지 못했어요. 내 코드의 문제가 아니에요. | 잠시 후 다시 제출해 주세요. 이 제출은 시도 횟수에 넣지 않아요. |

**런타임 에러 종류별 설명**

| 표시 | 쉬운 설명 |
|---|---|
| IndexError / Segfault | 리스트·배열에 없는 칸을 읽거나 썼어요(C++의 Segfault는 잘못된 메모리 접근 전반). 반복 범위와 배열 크기를 비교해 보세요. |
| ZeroDivisionError / DivisionByZero | 0으로 나눴어요. 나누는 값이 0이 되는 입력이 있는지 확인해 보세요. |
| ValueError | 값의 모양이 맞지 않아 변환하지 못했어요. 한 줄에 숫자가 여러 개인데 `int(input())`으로 읽지 않았는지 확인해 보세요. |
| NameError | 만들지 않은 변수나 함수 이름을 썼어요. 오타와 대소문자를 확인해 보세요. |
| TypeError | 서로 다른 종류의 값끼리 계산했어요(예: 문자열 + 숫자). |
| RecursionError / StackOverflow | 재귀 호출이 너무 깊어요. 종료 조건이 있는지, 깊이가 입력 크기만큼 커지지 않는지 확인해 보세요. |
| EOFError | 주어진 입력보다 더 많이 읽으려 했어요. 입력 줄 수를 다시 확인해 보세요. |

**판정 규칙**

- 출력 비교: 줄바꿈 문자(CRLF)와 출력 끝의 줄바꿈 한 개만 통일한 뒤 비교한다. 공백·줄바꿈만 다르면 ‘출력 형식이 잘못되었습니다’, 공백을 모두 지워도 다르면 ‘틀렸습니다’다.
- 런타임 에러 이름: Judge0가 돌려주는 신호(SIGSEGV·SIGFPE 등)와 Python 예외 이름을 위 표의 이름으로 바꿔 표시한다.
- 비공개 테스트에서 난 런타임 에러는 종류만 보여 준다. 입력값이 섞일 수 있는 메시지 원문과 줄 번호는 공개 예제 케이스에서만 보여 주고 AI에도 그 범위만 전달한다(예제 실행과 제출 결과 모두). 제출 채점은 공개 예제부터 실행해, 예제에서 난 에러를 먼저 보여 줄 수 있게 한다.
- 채점 서버 오류는 학생의 오답이 아니라 ‘채점 불가’로 표시하고 시도 횟수에서 뺀다.
